# 5.3 AI code review: result

Pull request: [robakiem/GenAI2026_Team03#1](https://github.com/robakiem/GenAI2026_Team03/pull/1), `feature/create-trip` → `main`, epic "Create a trip" (US-004, US-005, EP-02 … EP-09).

## Process

The review followed four levels, in this order:

1. **Deterministic checks.** `pnpm check` (typecheck, ESLint with `--max-warnings=0`, Vitest + Supertest, web build) ran before every push.
2. **Manual smoke test.** Browser at 360 px. Besides the happy path it covered:
   - an invalid e-mail and a short password on sign-up;
   - a trip name made only of spaces;
   - a duplicate member name;
   - the pages with the API stopped;
   - horizontal scroll.
3. **Local AI audit.** The read-only `code-reviewer` subagent reviewed `git diff main...feature/create-trip`.
4. **Review in the PR:**
   - The report was posted as a GitHub review, with one comment per finding on its line.
   - Before posting, the developer checked every finding against the code.
   - Fixes came as separate commits `fix(review): CR-xx …`.
   - Each thread got a reply naming the commit and how the fix was checked.
   - Threads were resolved after a re-review confirmed them.

The same subagent re-reviewed the fix commits until its verdict was APPROVE.

## Tool

- [`.claude/agents/code-reviewer.md`](../../.claude/agents/code-reviewer.md) is a project subagent with the tools `Read, Grep, Glob, Bash` and no Write or Edit. It reviews a diff against `CLAUDE.md`, `docs/adr/` and `docs/technical-contracts.md` with four checklists:
  - A: architecture and contracts;
  - B: security;
  - C: error handling;
  - D: code cleanliness and tests.
- Every finding has a stable ID (`CR-xx`), a severity (BLOCKER / MAJOR / MINOR / NIT), `file:line`, the rule it breaks, a concrete failure scenario and a suggested fix. In re-review mode, every previous finding gets a status.
- [`.claude/hooks/readonly-bash.js`](../../.claude/hooks/readonly-bash.js) is a PreToolUse hook of the subagent. It lets Bash run only a single read-only `git` command (`diff`, `log`, `show`, `blame`, …) made of printable ASCII. It refuses pipes, redirects, chaining, escapes, unquoted wildcards and options that write files or start programs. So the reviewer cannot change the code even if the reviewed code tells it to.

## Observations

- The reviewer found weaknesses in its own guardrail (CR-02). The fix then opened a new bypass (CR-17), which only the re-review caught. A single review pass would have merged it.
- Claims about library behaviour (Zod 4, Prisma 7, bcrypt) were confirmed by running them, not taken on trust.
- The AI only read the code; runtime behaviour was covered by the smoke test.

## Open questions for the team

1. **CR-06:** a plain SHA-256 pre-hash is open to "password shucking"; HMAC with a server-side secret avoids it. Was argon2 tried on Windows (the ADR-0005 condition for bcrypt)? Should ADR-0005 record the bcrypt fallback and the pre-hash?
2. The developer approved the new `uk.fieldErrors` texts. Does the team agree (CLAUDE.md §6)?
3. `trust proxy 1` assumes exactly one TLS-terminating proxy. Where should the deployment topology be documented?
4. Sign-in checks only that the fields are not empty, so every failure reads as `INVALID_CREDENTIALS`. Is this the intended reading of EP-03?
5. The order of the EP-07 list is not specified. Today the oldest trip comes first.
6. Possible lost writes under concurrency in the SQLite adapter (unverified). The concurrency test that ADR-0006 asks for would settle it.
7. A request body over 100 kB ends in 500 `INTERNAL_ERROR`, and the catalogue has no code for it.
8. There are no Ukrainian texts yet for `SETTLEMENT_STARTED` / `LEDGER_CLOSED`; they cannot occur in this slice.
