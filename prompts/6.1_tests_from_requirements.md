<method>
The trap to avoid: asking for tests of existing code makes the model accept a bug as the norm. So the order is fixed:

1. **Tests first, from the requirements only.** Before any production code, write the tests from the Gherkin scenarios, checklists and contracts:
   - pure functions in `packages/shared` (split, balances, transfers, breakdown, parsing amounts and percentages): every example table of US-016, US-019, US-020-a, US-020-b, US-044, US-048, US-030 and the "Carpathians" data;
   - services against a real SQLite file: refusals (MEMBER_NOT_IN_LEDGER, AMOUNT_TOO_SMALL with `participantCount`, SHARES_SUM_MISMATCH with `differenceKopecks`, PERCENT_SUM_MISMATCH with `differenceBp`), freeze and closed ledger, idempotent repeat by `clientRequestId`, another Coordinator's ledger, the member page privacy (BR-40, BR-41, BR-43);
   - HTTP with Supertest: the whole Carpathians flow, invalid amounts (`OUT_OF_RANGE`, `NOT_AN_INTEGER`, `INVALID_TYPE`), no participants (`TOO_FEW_ITEMS`), duplicates (`DUPLICATE_ITEM`), 201 vs 200 on repeat, payment details 100/101 characters, 401 and an ignored cookie on link routes.
   Cover not only the happy path: boundaries (0.01 each, 999999.99), errors, permissions. Test names = scenario names.
2. **Red.** Run `pnpm test` and record that the new tests fail because the code does not exist.
3. **Green.** Implement in layer order `shared → data → services → routes → web` until every test passes. Do not change a test to fit the code; if a test looks wrong, check the requirement and report.
4. **Mutation check.** Break three money rules on purpose (leftover kopecks by selection order; rounding percentages to nearest; transfers not sorted by debtor) and confirm that the matching scenarios fail. Restore the code.
5. **UI.** Build the screens (expense form with three split modes and live preview, "who pays whom", the friend's page with copy of details) in the style of the reference: cream background, raspberry pink, sky blue, leaf green and yellow accents, scalloped edges, flower-shaped avatars, bold sans headings with an italic serif accent word. Texts only in `i18n/uk.ts`, 360 px without horizontal scroll.
6. Run `pnpm check`, then report changed files, covered rules and anything not verified.
</method>
